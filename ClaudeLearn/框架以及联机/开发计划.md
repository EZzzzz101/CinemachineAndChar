# 一周联机动作Demo — 架构方案（第二版）

## Context

仿绝区零的第三人称动作游戏，作为客户端校招作品集demo。目标：**一周多时间，两人联机打怪的副本战斗demo**。

关键设计决策：**主世界（单人）←→ 副本（联机）**，网络代码只在副本内激活。

---

## 整体游戏流程

```
[主世界 — 纯单人]
├── 跑图、对话NPC、看风景
├── 走到副本入口
│   └── 选择："创建副本" 或 "加入副本"
│
├── 创建副本 → 加载副本场景 → 成为Host（服务端+玩家）
│   ├── 启动TCP服务端（等待好友连入）
│   ├── 启动UDP（位置同步）
│   ├── 生成怪物，怪物的行为树在Host上跑
│   └── 自己的角色 = 本地控制 + 位置/攻击发UDP/TCP广播
│
├── 加入副本 → 连Host IP → 加载副本场景 → 成为Client
│   ├── TCP连上Host → 收到全量同步（怪物位置/血量/队友位置）
│   ├── 自己的角色 = 本地控制
│   └── 远程角色/怪物 = UDP插值平滑
│
└── 打完/退出 → 断网 → 回到主世界单人
```

**核心原则：** 主世界完全不需要网络，网络只在副本场景里存在。对话/NPC/存档全是单人的事。

## 模块一：网络联机（Protobuf + TCP/UDP）

### 网络只在副本场景存活

```csharp
// 进入副本时触发
GameServer.Instance.StartHost(port);   // 创建者：启动TCP+UDP
// 或
NetworkClient.Instance.Connect(ip, port); // 加入者：连Host

// 退出副本时
GameServer.Instance.Shutdown();        // 关TCP+UDP
// 或
NetworkClient.Instance.Disconnect();
```

### 消息协议（protobuf-net 属性标记）

```csharp
public enum MsgType : short
{
    // TCP 可靠消息
    Handshake       = 1,  // Client→Host：请求加入副本
    HandshakeAck    = 2,  // Host→Client：分配PlayerID+副本全量状态
    PlayerInput     = 10, // Client→Host：输入状态（用于动画同步优化，可选）
    AttackRequest   = 11, // Client→Host：请求攻击
    AttackResult    = 12, // Host→所有：攻击结果（damage/hitPoint）
    StateSync       = 20, // Host→Client：全量状态同步（连入时+定期校正）
    EntityDeath     = 21, // Host→所有：怪物/玩家死亡
    DungeonComplete = 30, // Host→所有：副本通关
    ChatMessage     = 40, // 简单的文字聊天（可选）

    // UDP 高频更新
    TransformUpdate = 100, // 位置/旋转同步
}
```

### 攻击同步数据流（和上一版相同，现在只发生在副本内）

```
Client 按攻击键
  → 本地立刻播动画（手感瞬间响应）
  → ATK() 动画事件 → 发 TCP AttackRequest
  → Host CombatValidator 验证（距离/存活/冷却）
  → 通过 → 更新怪物血量 → TCP广播 AttackResult
  → 所有客户端：打击特效 + 伤害数字 + 血条更新
```

## 模块二：UI系统（MVC + 对象池）

### MVC 分工

```
Model（数据层）
├── 不单独建 Model 文件夹
├── 数据在各自的组件里：PlayerController.CurrentHP、TargetManager、SaveData
└── UI Controller 需要时直接从这些源头读取，不做数据副本

View（显示层）
├── 继承 UIView，挂载在 Canvas 下的 GameObject 上
├── 只负责"怎么显示"（SetHP(ratio) / Show() / Hide()）
├── 不持有数据，不订阅事件
└── 只有 Controller 调它

Controller（控制层）
├── 继承 MonoBehaviour，挂载在场景中
├── 订阅 EventBus 通知 → 从数据源读取最新值 → 调 View 刷新
└── 是数据源和 View 之间的桥梁
```

### 数据流

```
某个数据变化（如 PlayerController.HP 改变）
         │
         │ Emit("player.hp.changed")
         ▼
     EventBus
         │
         │ 通知所有订阅的 Controller
         ▼
PlayerHUDController.OnHPChanged()
  → 从 PlayerController 读 CurrentHP / MaxHP
  → 调 _view.SetHP(ratio)
  → PlayerHPBarView 更新血条显示
```

### 界面规划

```
[主世界UI]                          [副本UI]
├─ 主菜单（开始游戏/读档/设置）       ├─ 副本HUD
```

## 物理部署流程（实际跑起来的样子）

```
[场景一：Overworld.unity]
单人模式
├── 玩家：PlayerEntity.isLocalPlayer = true，正常跑FSM
├── NPC们：挂DialogueTrigger，本地交互
└── 副本入口：一个Trigger Volume + UI交互

[玩家在副本入口选"创建副本"]
  → GameManager切换到DungeonLoading状态
  → 加载Dungeon.unity（按需加载）
  → GameServer.StartHost(port) 开TCP/UDP
  → GameManager切换到Dungeon状态
  → 怪物生成，AI跑在Host上

[朋友选"加入副本"，输入Host的IP]
  → 加载Dungeon.unity
  → NetworkClient.Connect(ip, port)
  → TCP Handshake → 收到全量StateSync
  → GameManager切换到Dungeon状态

[副本中]
  Host: 本地角色(直接控制) + 服务端(怪物AI/战斗验证/转发数据)
  Client: 本地角色(直接控制) + 远程角色(插值)

[打完/退出]
  → 断开TCP/UDP
  → 卸载Dungeon.unity
  → 回到Overworld.unity
  → GameManager回到Overworld状态
```

## 关键风险

| 风险 | 缓解 |
|------|------|
| 一周时间不够 | Phase1-2先保网络链路通，单人内容（对话/A*寻路）可以砍 |
| 异步Socket线程问题 | 用 `ConcurrentQueue<Action>` 队列，主线程Update消费 |
| UDP丢包 | 每个包带序列号，丢弃过期包，插值平滑 |
| 副本场景切换时网络中断 | **先断网→再切场景**，不要在场景加载时保持连接 |
| protobuf-net Unity兼容性 | 用 `.NET Standard 2.1` API兼容级别，装对应版本dll |
